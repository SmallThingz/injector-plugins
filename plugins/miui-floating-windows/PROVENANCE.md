# MIUI floating windows provenance

The archive places `plugin.json`, the hooks and both payloads at its root. There is no boot trigger. Enable and Run pass the saved integer limit, default 3. Disable requests disposal of the current session. Each run directory retains its diagnostic log and ownership evidence in plugin state.

## Bounded review of startup and ordinary local attachment

* **Policy loading.** The original Android injector, server and test runner each call `frida_selinux_patch_policy` during startup. `frida_init_with_runtime` also initializes GLib, GIO and Gum. The common Meson library now compiles `policy-disabled.c`, whose function returns without performing any operation. The original `patch.c` is absent from the compilation database. [Injector startup](https://github.com/frida/frida-core/blob/1c41f2396787436d207e8b2f21569316f7a06f38/inject/inject-glue.c) · [Runtime initialization](https://github.com/frida/frida-core/blob/1c41f2396787436d207e8b2f21569316f7a06f38/src/frida-glue.c)
* **Enforcement mode.** The excluded policy writer contains both the write to `/sys/fs/selinux/load` and its `security_setenforce(0)` retry and restoration. The replacement has no such calls. [Original policy writer](https://github.com/frida/frida-core/blob/1c41f2396787436d207e8b2f21569316f7a06f38/lib/selinux/patch.c)
* **File labels.** The patch removes the four `setfilecon`/`fsetfilecon` requests in `linjector.vala` and `pipe.vala` for Frida's directory, file, memfd and socket. The kernel supplies labels under existing policy. [Linjector](https://github.com/frida/frida-core/blob/1c41f2396787436d207e8b2f21569316f7a06f38/src/linux/linjector.vala) · [Socket](https://github.com/frida/frida-core/blob/1c41f2396787436d207e8b2f21569316f7a06f38/lib/pipe/pipe.vala)
* **Process domains.** The plugin selects Injector's root backend, checks UID and uses the supplied identity. The helper and crash monitor no longer try nested `su`. No plugin command requests a process-domain transition. The remaining `selinux_android_setcontext` references are in child monitoring/spawn code. The spawn wrapper forwards Android's original arguments and return value, and the fork listener observes specialization. The plugin attaches to a PID and does not request spawn or child gating. [Zygote wrapper](https://github.com/frida/frida-core/blob/1c41f2396787436d207e8b2f21569316f7a06f38/src/linux/helpers/zymbiote.c) · [Fork listener](https://github.com/frida/frida-core/blob/1c41f2396787436d207e8b2f21569316f7a06f38/lib/payload/fork-monitor.vala)
* **Denial.** The pinned helper normally has additional attach paths. The patch removes the kernel backend selection and permission-denial fallback from the local attach task. An initial ptrace refusal propagates immediately. Memory read/write permission errors also propagate. Agent startup declines executable-memory denial locally. The CLI prints the attach error and returns 4. `MIUI_NO_AGENT` means the CLI never started the window-limit script. It makes no assertion about success of a device operation. [Original helper](https://github.com/frida/frida-core/blob/1c41f2396787436d207e8b2f21569316f7a06f38/src/linux/frida-helper-backend.vala)

## Rollback evidence

The original CLI suppresses errors in its init RPC. The candidate propagates them and acknowledges readiness only after `ScriptRunner.start` returns. The stop request uses a fresh private run directory. The wrapper serializes changes with `flock`, records boot ID, PID and `/proc` start time, and never signals by PID. Startup and disposal have cancellation deadlines. The shell waits at most 16 seconds for its prior process and 25 seconds for the next readiness receipt, apart from filesystem and utility execution time.

The client explicitly calls the agent's `dispose` RPC **before** `Session.detach`. The existing agent sets `hook.implementation = null`. Bridge 7.1.0 calls `mangler.revert(vm)` for an existing replacement. The ART implementation restores the saved method, deletes the replacement mapping and deactivates its interceptor when present. Frida's normal `Session.detach` requests session closure and closes its scripts. The script engine also attempts disposal on unload, but catches RPC errors. This is why the wrapper requires the separate successful disposal response, detach return and disappearance of the owned process. A missing receipt with a stale PID remains unknown. The evidence covers the overridden method. Live stock-window behavior and restoration on this firmware are unverified. [Bridge setter](https://github.com/frida-packages/frida-java-bridge/blob/f9d1620947f926fa0f5c8ba2095666be74fb2e36/lib/class-factory.js#L1712-L1723) · [ART revert](https://github.com/frida-packages/frida-java-bridge/blob/f9d1620947f926fa0f5c8ba2095666be74fb2e36/lib/android.js#L3809-L3821) · [Session detach](https://github.com/frida/frida-core/blob/1c41f2396787436d207e8b2f21569316f7a06f38/src/frida.vala#L4275-L4277) · [Script disposal](https://github.com/frida/frida-core/blob/1c41f2396787436d207e8b2f21569316f7a06f38/lib/payload/script-engine.vala#L420-L448)
